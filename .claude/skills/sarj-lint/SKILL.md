# Sarj lint rules

Ten rules run on every file in `src/`, enforced by `npm run lint`. They are the
machine-checkable half of `sarj-mockup`. Write code that passes them the first
time — do not write it loosely and clean up after the linter.

**Everything below applies to code you author. `src/components/ui/` is exempt**
— those files are generated by `npx shadcn@latest add`, which would overwrite
any change on the next run.

## The whole thing in one table

| Rule | Never write | Write instead |
|---|---|---|
| `no-raw-color` | `bg-[#392868]`, `text-gray-500`, `bg-white`, `style={{ color }}` | `bg-primary`, `text-muted-foreground`, `bg-card text-card-foreground` |
| `no-arbitrary-scale` | `gap-[13px]`, `rounded-[10px]`, `text-[0.625rem]` | `gap-3`, `rounded-lg`, `text-xs` |
| `no-shadow` | `shadow-md`, `hover:shadow-lg`, `drop-shadow-*` | `<Card>` (it rings), or an overlay primitive |
| `z-index-tokens` | `z-50`, `z-[9999]` | `z-modal`, `z-popover`, `z-toast` |
| `use-ui-primitives` | `<button>`, `<input>`, a `<div>` shaped like a Card | `<Button>`, `<Input>`, `<Card>` |
| `no-primitive-override` | `<Button className="h-10 px-4 rounded-md">` | `<Button size="lg">` |
| `icon-source` | `import { X } from "lucide-react"` | `@hugeicons/react` + `@hugeicons/core-free-icons` |
| `motion-tokens` | `duration-500`, `ease-out`, `ease-[cubic-bezier(…)]` | `duration-200`, `ease-out-cubic` |
| `motion-reduce` | `transition-colors` on its own | `transition-colors motion-reduce:transition-none` |
| `no-layout-animation` | `transition-all`, `transition-[width]` | `transition-transform`, `transition-opacity` |

## Tokens

### `sarj/no-raw-color` — every colour is a semantic token

A literal colour is not a style preference, it is invisible breakage. This app
ships three themes: light, `.dark`, and the `[data-whitelabel="tasama"]`
whitelabel. A token follows all three. `bg-[#392868]` and `text-gray-500` follow
none of them, so the mockup silently looks wrong in two thirds of the app.

Banned: `#hex` · `oklch()` `rgb()` `hsl()` `color-mix()` · every raw Tailwind
palette class (`bg-red-500`, `text-slate-400`, `border-zinc-200`) · `bg-white`
and `text-black` · colour keys in a `style` prop · raw colours in `fill=` /
`stroke=` / `color=` props.

The complete set of colour names — there are no others:

**Surfaces** `background` `card` `popover` `muted` `secondary` `accent` `sidebar`
**Text** `foreground` `muted-foreground`, plus the `-foreground` pair of every surface
**Brand** `primary` `primary-tint` `primary-highlight` `primary-light` `primary-dark`
**Intent** `destructive` `warning` `success` — each with a `-foreground`
**Lines** `border` `input` `ring`
**Charts** `chart-1` … `chart-6` — one purple ramp, darkest first, never a rainbow

Always pair a surface with its own foreground (`bg-primary text-primary-foreground`)
so contrast survives a theme flip.

`style` is for **dynamic geometry only** — `style={{ height: `${pct}%` }}` on a
bar is fine, `style={{ background: brandColor }}` is not.

### `sarj/no-arbitrary-scale` — spacing, radius, and type come off the scale

`gap-[13px]` lands half a step off every neighbour and quietly breaks the 4px
rhythm. That is the difference between a mockup that reads as built and one that
reads as assembled.

Banned: an arbitrary `[…]` value on any padding, margin, gap, width, height,
inset, translate, radius, `text-`, `leading-`, or `tracking-` utility.

- Spacing: `gap-2` (8px) · `gap-3` (12) · `gap-4` (16) · `gap-6` (24) · `gap-8` (32)
- Radius: `rounded-sm | md | lg | xl | 2xl | 3xl | 4xl`, all derived from `--radius`
- Type: `text-xs | sm | base | lg | xl | 2xl…` — **never below `text-xs`**

Allowed through, because the scale has no equivalent: viewport-relative values
(`max-h-[86vh]`, `max-h-[calc(90vh-8.75rem)]`) and anything containing `var(--…)`.
Grid track definitions (`grid-cols-[auto_1fr]`) are not checked.

Say "less important" with `text-muted-foreground`, not a smaller font.

### `sarj/no-shadow` — mockups are flat

Depth here comes from `ring-1 ring-foreground/10` and from surface tokens
(`bg-card` on `bg-background`, a `bg-muted` inset), not from a drop shadow. The
primitives that genuinely float already carry their own shadow, so a
hand-written one only adds a second, mismatched elevation language.

Banned: every `shadow-*`, `drop-shadow-*`, `inset-shadow-*`, `text-shadow-*`,
and `boxShadow` in a `style` prop. `shadow-none` stays legal — removing a shadow
is always in the flat direction.

- Raised surface → `<Card>`, which brings its own ring
- Inset panel → `bg-muted rounded-lg p-4`
- Genuinely floating → it is an overlay: `Dialog`, `Sheet`, `Popover`, `DropdownMenu`

### `sarj/z-index-tokens` — name the layer, don't pick a number

`z-50` tells the next reader nothing about what this is meant to sit above. When
two people both reach for 50 the layering becomes a race, and the usual fix is
someone typing `z-[9999]`.

The scale, from `globals.css`:

| Class | Value | For |
|---|---|---|
| `z-base` | 0 | normal flow |
| `z-raised` | 10 | sticky table header, hover lift |
| `z-sticky` | 20 | sticky page toolbar / filter bar |
| `z-nav` | 30 | app sidebar, top nav |
| `z-overlay` | 40 | scrim behind a panel |
| `z-modal` | 50 | dialog, sheet, drawer content |
| `z-popover` | 60 | popover or select opened inside a modal |
| `z-toast` | 70 | toasts |
| `z-tooltip` | 80 | always on top |

`z-modal` is 50 — the same value the shadcn overlays use — so anything that must
sit above a dialog is `z-popover` or higher. Never a bigger number.

## Primitives

### `sarj/use-ui-primitives` — 61 are installed; almost nothing needs building

A hand-rolled `<button>` gets the brand's colour but not its focus ring, its
disabled state, its icon sizing, its hover timing, or its dark-mode pairing —
and each new mockup drifts a little further.

| Raw | Use |
|---|---|
| `<button>` | `<Button>` — sizes `xs \| sm \| default \| lg`, `icon-xs \| icon-sm \| icon \| icon-lg` |
| `<input>` | `<Input>`, or `<InputGroup>` when it needs an addon |
| `<textarea>` | `<Textarea>` |
| `<select>` | `<Select>`, or `<NativeSelect>` |
| `<table>` | the `<Table>` family |
| `<dialog>` | `<Dialog>` |
| `<progress>` | `<Progress>` |
| `<hr>` | `<Separator>` |

Also caught: a `<div>` carrying a radius **and** an edge (`border`/`ring`) **and**
padding. That is `<Card>` with extra steps — and Card owns its padding via
`--card-spacing` and uses `ring-1 ring-foreground/10`, so you write neither.

**Not caught, because it is correct:** a raw element as the child of an
`asChild` primitive. `<Item asChild><button …>` is the idiomatic pattern — asChild
merges the primitive's props onto the child, so the child has to be a raw element.

Missing something genuinely? `npx shadcn@latest add <name>`. Do not hand-roll it.

### `sarj/no-primitive-override` — a primitive's className is for layout

`<Button className="h-10 rounded-md px-4">` does not customise the button, it
forks it: the override freezes while the primitive keeps evolving, until this
one button no longer matches any other button in the app. If a primitive needs
to look different, that is a `variant` or a `size`, not a class.

Checked primitives, and what each owns:

| Primitive | Owns | Change it with |
|---|---|---|
| `Card` | padding, radius, edge | `size="sm"` for dense tiles |
| `CardHeader` `CardContent` `CardFooter` | padding | — Card owns the whole stack |
| `Button` | padding, radius, height | `size`, `variant` |
| `Badge` | padding, radius, height | `variant` (already a pill: `rounded-4xl h-5 text-xs`) |
| `Input` `SelectTrigger` `InputGroup` | padding, radius, height | `size` |
| `Textarea` | padding, radius | `rows` |
| `CardTitle` `CardDescription`, and every `DialogTitle` / `SheetTitle` / `AlertTitle` pair | type size, font weight | nothing — they have a fixed rung on the ladder |

**Deliberately narrow — two things it does NOT check:**

1. **Colour on a primitive is fine when it is a token.** `bg-primary-tint` on an
   `<Item>` is the sanctioned selected-row surface; `text-muted-foreground` on a
   `<TableCell>` is the sanctioned secondary text. Tokens are the vocabulary.
   `no-raw-color` already catches the colours that are not tokens.
2. **Layout wrappers are not checked** — `ScrollArea`, `CollapsibleContent`,
   `TabsContent`, `DialogContent`, `SheetContent`. They exist to be laid out;
   `h-60` on a ScrollArea is required, not a violation.

Always legal on any primitive: `col-span-*`, `w-full`, `max-w-*`, `flex`, `grid`,
`gap-*`, `mx-auto`, `items-*`, `justify-*`, `self-*`, and every margin.

## Icons

### `sarj/icon-source` — HugeIcons in authored UI

Mixing icon sets is the fastest way to make a design system look assembled
rather than built: stroke weights disagree, optical sizes disagree, and a
"settings" gear stops matching the corner radius of everything around it. The
tell is subtle per icon and obvious per screen.

```tsx
import { HugeiconsIcon } from "@hugeicons/react"
import { Settings01Icon } from "@hugeicons/core-free-icons"

<HugeiconsIcon icon={Settings01Icon} />
```

See `src/components/transfer-routing/icons.tsx` for the pattern used here.

Banned in authored code: `lucide-react`, `@tabler/icons-react`, `react-icons`,
`@heroicons/react`, `@radix-ui/react-icons`. Emoji are never icons.

**`lucide-react` stays legal inside `src/components/ui/`** — every
`npx shadcn@latest add` writes those imports back in, so policing them would
mean re-patching the primitives forever for no visual gain.

Sizing: 16px inline with 14px text, 20px with 16–18px, 24px+ only standalone.
The primitives size icons automatically — if you are writing `size-*` on an icon
inside a `Button`/`Badge`/`Item`, you are fixing the wrong thing.

33 files still import lucide and warn rather than error while they are migrated;
they are listed in `eslint.config.mjs`. **Do not add to that list.**

## Motion

The full reasoning lives in the `web-animation-design` skill. These three rules
enforce its house rules.

### `sarj/motion-tokens` — duration and easing are tokens

| Interaction | Duration |
|---|---|
| hover, press | `duration-150` |
| tooltip, popover, dropdown | `duration-200` |
| dialog, drawer | `duration-200` … `duration-300` |
| a container morphing to fit new content | `duration-250` … `duration-300` |

Nothing over 300ms. Past that a UI animation stops reading as feedback and
starts reading as latency. Larger elements animate slower than small ones, but
never longer than that.

Easing — only these three:

- **`ease-out-cubic`** — anything entering or leaving the screen. The fast start
  makes the UI feel like it reacted instantly.
- **`ease-in-out-cubic`** — an on-screen element moving or resizing. Accelerate,
  then brake, like real motion.
- **`ease-linear`** — constant motion only: marquees, progress, spinners.

`ease-in` is banned outright — a slow start delays the visual feedback the user
is waiting for, which is what makes an interface feel sluggish. Plain `ease-out`
and `ease-in-out` are the browser's untuned curves; use the `-cubic` tokens.
Never write a raw `cubic-bezier()` in a component.

### `sarj/motion-reduce` — every animated element carries its own escape

```tsx
className="transition-colors duration-150 motion-reduce:transition-none"
className="animate-in fade-in-0 duration-200 motion-reduce:animate-none"
```

Not optional, and **no exception for opacity or colour**. "It's only a fade" is
the same argument made once per element, and the sum is a page that still moves.
Anyone with `prefers-reduced-motion` on has already told their OS that
unrequested movement makes them ill — it is a physical symptom, not a taste.

It is per-element because Tailwind has no global kill-switch: `motion-reduce:`
compiles to a media query scoped to the class it prefixes.

Enter animations come from `tw-animate-css`, imported globally — `animate-in`,
`fade-in-0`, `zoom-in-95`, `slide-in-from-bottom-1`. Don't hand-write keyframes
for these. Prefer `slide-in-from-bottom-*`: left/right do not mirror under RTL.

### `sarj/no-layout-animation` — transform and opacity only

Those two are the only properties the browser hands to the compositor: they skip
layout and paint and run on the GPU. Animating `width`, `height`, `padding`, or
`top` forces a layout recalculation every frame — for the element *and*
everything that reflows around it. That is the jank people call "cheap".

`transition-all` is how this happens by accident: it opts in every property that
changes, so an unrelated class change starts animating a layout property. Name
what actually moves — `transition-transform`, `transition-opacity`,
`transition-colors`.

A size change is usually `scale`. A position change is usually `translate`.
Start an element from `scale(0.95)`, never `scale(0)`.

**The one exception**, from the house rules: a container morphing to fit new
content may animate `height`, on a wrapper measuring its child with a
`ResizeObserver`. It is allowed because switching a settings section is a rare
interaction, not a 100×/day one. Mark it:

```tsx
// eslint-disable-next-line sarj/no-layout-animation -- ResizeObserver container morph
"transition-[height] duration-300 ease-in-out-cubic motion-reduce:transition-none"
```

Anywhere frequent, don't animate height at all. And remember the frequency
principle: something a user sees 100+ times a day should not animate.

## Escape hatches

There is one, and it is deliberately noisy:

```tsx
// eslint-disable-next-line sarj/<rule> -- <why this case is genuinely different>
```

Always on a single line, always with a reason. A file-level `/* eslint-disable */`
hides every future violation in that file too — never use one.

If you find yourself wanting a disable, the answer is almost always that a
primitive, variant, or token already covers the case.

## Before you finish

1. `npm run lint` — zero `sarj/*` errors in files you touched.
2. `npm run build` — it must compile.
3. Grep your own output for `#`, `oklch(`, `rgb(`, `style={{` — zero hits.
4. Mentally toggle `class="dark"` on `<html>`: does anything go invisible? If you
   used only tokens, no.
